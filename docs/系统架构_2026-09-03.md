# 系统架构：从论文的形状，变成系统的形状（2026-09-03）

> **一句话**：现在的仓库是「做一次实验的实验室」，要变成「每天能开门的小店」。
> 缺的不是算法，是三样——信号得有插槽（能插第二个）、组合和下单得从脚本里搬出来、
> 每天得有一条固定流程。
> 本文只描述架构，**不改代码、不动协议**。

---

## 1. 标准该有什么 / 我们有什么 / 好不好

| 层 | 这层负责什么 | 本仓库现在是什么 | 判断 |
|---|---|---|---|
| **数据** | 原始行情 → 干净可复现的面板与标签 | `src/crsp_pipeline/`：`snapshot` `universe` `adjust` `cleaning` `calendar` `labels` `splits`；入口 `scripts/prepare_data.py`、`scripts/emit_folds.py` | **好**。折边界机械生成不手写，复权双路验证，purge 有断言 |
| **信号** | 面板 → 「每只股票今天几分」 | `src/kronos_ft/`：`windows` `dataset` `models` `train` `infer` `represent`；入口 `scripts/evaluate_fold.py` | **好，但只装得下一个**。整层为 Kronos 一个模型而写，没有「第二个信号往哪插」的位置 |
| **组合** | 分数 → 「今天持有哪 50 只、买卖哪些」 | **没有独立模块**。top500 / 进前 10% / 跌出前 30% / 六袖套 / 等权 / t+1 开盘建仓，这套规则只活在 `scripts/compare_arms_money.py` 与 `analysis_sevenfold.py` 里，各抄了一份 | **能用，要归拢**。全项目的钱由这段逻辑决定，它却躺在两个分析脚本里 |
| **回测 / 评估** | 算 IC、收益、显著性 | `crsp_pipeline/signal_eval.py`（RankIC / NW t / 十分位 / 中性化）、`execution_sim.py`、`costs.py`、`scripts/bootstrap_errorbars.py` | **好**。统计工具齐了，不要再造 |
| **执行** | 真把单子发出去、记下成交了什么 | **完全没有**。券商已定 Alpaca，费率、碰撞规则、影子账本全部只在文档里 | **缺**。钱的路径上唯一空着的一格 |
| **监控** | 每天自动看一眼「今天正常吗」 | 只有训练日志 `outputs/**/_logs/`、`sealed_run.log`、每折的 `metrics.json` | **缺**。没有「今天该看的十个数」这样一份固定输出 |
| **研究纪律** | 防止自己骗自己 | `CLAUDE.md`、`experiments/ledger.md`（append-only）、三份协议、`crsp_pipeline/sealed.py` 的封存哨兵与读取守卫、`leak_check.py`、121+ 条测试 | **全项目最强的一层**。别处通常没有，改架构时别把它弄松 |

七层里三层好（数据、评估、纪律），一层好但没开口（信号），一层散在脚本里（组合），两层空白（执行、监控）。
**这正好对应今晚新增的四个包。**

## 2. 今晚新增的四个包

以下是**接口约定**，不是实现细节；三位工程师并行写。

| 包 | 里面有什么 | 关键约束 |
|---|---|---|
| `src/signals/` | `SignalSpec`（一个信号的冻结身份证：名字/参数/出处/spec_hash）；`Signal.compute(panel) -> [signal_date, PERMNO, score]`；`overnight_intraday.py`（信号#2）；`kronos_adapter.py`（把已算好的 Kronos 分数包成同样三列） | 三列格式对谁都一样。`kronos_adapter` **只读已消耗的开发折**：折号白名单硬编码，读之前先调 `sealed.assert_readable`。信号#2 的规格已在 `experiments/signal2_prereg_v1.md` §1 逐字冻结，**没有可调超参** |
| `src/portfolio/` | `construction.frozen_long_only_returns`（从 `scripts/compare_arms_money.py` 抽出）；`combine.rank_sum_equal_weight`（两信号名次相加、等权）；`combine.slow_filter`（慢信号排前一半才可持有，快信号在里面按老规矩挑） | 抽出必须**逐位**——一个数都不改 |
| `src/backtest/` | 把「信号 + 组合规则」跑成一条日收益序列 | **薄包装**：统计量全部复用 `crsp_pipeline.signal_eval`，**一个新指标都不引入** |
| `src/execution/` | `collision`（SHA-256 让位）；`shadow_ledger`（两臂各记一本虚拟账）；`fees`（Alpaca Elite 费率）；`alpaca_client`（**默认 dry-run**）；`daily_flow`（把上面串成每天一次的流程） | 碰撞让位**禁止用 Python 内置 `hash()`**（每个进程都不一样，等于没规则）；真下单必须显式开关 |

三条要点：

1. **插槽的意义**：有了统一的三列，第三个、第四个信号只是多一个文件，
   不用再动数据层、评估层、组合层任何一行。
2. **「逐位抽出」不是修辞**：改了任何一个数，就不是同一个策略，
   历史上所有读数（毛 10.48%/年、BE 21.9bp、夏普 0.72）全部作废。
3. **两个合成函数都要写**，但用哪一个不由代码决定，由 `signal2_prereg_v1.md` §4 的三分处置决定——
   那份判据在看到任何数据之前就写死了，看完数据就不许再选。
4. **让位为什么必须有影子账本**：一臂当天被让掉之后，第二天就说不清它本来该买什么。

## 4. 每天怎么跑（协议 §5，一段话）

收盘之后，先用两臂各自的**虚拟账本**加上当天的分数，各算出「今天该持有哪些」，
减掉各自现有的虚拟持仓，得到两份**理想订单**；
把两份订单放一起做碰撞检查——同一只股票一边买一边卖的，按哈希规则让一臂当天站开，
同一只股票同方向的，合并成一笔按名义额比例分配；
剩下的就是**可执行订单**，当晚 7 点之后、次日早上 9 点之前提交（美东时间；
9:28 以后交易所不再收进开盘竞价的单子，所以要留缓冲）；
第二天开盘成交回报回来，按同样的比例规则**分回**两本虚拟账本；
最后逐只股票核对「两本虚拟账加起来 == 真实账户持仓」，
**对不上就当天停机查清楚，那天不计入观察日数**。
全程记录的是「成交价 vs CRSP 开盘价」的分布，**不是盈亏**——小试要测的是成本，不是赚没赚。

## 5. 明确不做的三件事

- **不引 vectorbt。** 它是给「一个资产、一条时间序列」用的，我们做的是「几百只里挑 50 只」，
  形状不对；而且它的核心卖点是快速扫参数组合，那正是本项目纪律明令禁止的事。
- **不引 LLM 决策回路。** 训练语料里有没有未来信息**无法量化**，同样输入两次输出可能不同（不可复现），
  而它带来的效应量小到现有样本根本测不出来——**过不了 `CLAUDE.md` §二的功效关**，
  等于花钱买一个不可判读的结论。
- **不上大框架。** 两三个信号的个人系统要的是**五个模块**，不是一个框架。
  框架的价值是让一百个人协作，代价是所有东西都得按它的方式写；
  我们只有一台机器和一个人，代价全付了，价值一分没拿到。
