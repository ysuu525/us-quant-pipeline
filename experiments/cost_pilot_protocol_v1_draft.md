## 0. 目的、估计量、以及一个结构性盲点

**目的**：测出进入 `净 = 毛 − d × C` 的那个 `C`，为 FT 与 ZS **各测一个**。

**估计量**（每臂，按成交名义额加权；本策略每笔名义额恒等，故等价于逐笔等权均值）：

```
买入： C_i = (fill_i − DlyOpen_i) / DlyOpen_i × 1e4   [bp]
卖出： C_i = (DlyOpen_i − fill_i) / DlyOpen_i × 1e4   [bp]
       + 该笔的实际全包费用 / 名义额 × 1e4           [bp]
```

`DlyOpen` = 回测建仓价，见 `src/crsp_pipeline/labels.py:118-128`（t+1 原始未复权开盘价）。

**不进入 C 的东西**：决策收盘 → 开盘的漂移。回测也吃了这一段，计入即重复相加。
它作为诊断单独报告。

### 0.1 结构性盲点（必须写进最终报告的局限一节）

**`fill − DlyOpen` 在原理上无法识别自己对开盘印价的冲击。** MOO 单参与 opening cross
并共同决定那个印价；你的单子推高印价时，基准 `DlyOpen` 跟着一起动。所以本小试
**测不出自有冲击**，只能测出「相对竞价印价的执行偏差 + 费用」。

两条后果：

1. **不得**为了「提高竞价参与率、好感受印价」而选更大的 AUM——那不会揭示冲击，
   只会让基准被自己污染。AUM 只能由**真实的目标部署规模**决定（见 §1）。
2. 自有冲击必须由别的证据来源承担：现有容量分析（$1M 下 ≤1.3bp、$30–50M 才咬人），
   或将来一次**显式变更规模**的设计。本协议不承担该职责。

## 4. 碰撞处理：逐碰撞确定性哈希让位

**背景**：Alpaca 的市价/止损单**总是**被同标的反向的市价/限价/止损/止损限价单挡下
（HTTP 403），**paper 账户同样执行**。限价单只在「买限价 ≥ 卖限价」时挡，
而 LOO 要保证竞价成交必须给激进限价、两边必然交叉，**因此 LOO 逃不掉**。
例外只有 bracket / OCO / trailing stop，与本策略无关。

**规模**：2,270 笔反向碰撞落在 **729 / 832 = 87.6% 的交易日**上，
均值 2.7 笔/日、p90 5、max 15。**不是边缘情况，必须有预注册规则。**

### 4.1 规则（B4 = 单账户时适用）

对每一个发生反向碰撞的 `(trade_date, PERMNO)`：

```python
import hashlib
SEED = "k14-collision-yield-v1"          # 第一笔成交前写死，此后不得更改
def winner(trade_date, permno) -> str:
    msg = f"{SEED}|{trade_date.date().isoformat()}|{int(permno)}".encode()
    return "FT" if (hashlib.sha256(msg).digest()[-1] & 1) == 0 else "ZS"
```

**获胜臂照常提交该笔订单；落败臂当日在该标的上站开、不提交。**
单边不存在反向订单，403 不触发。

**禁止使用 Python 内置 `hash()`**（进程间随机化，不可复现）。

**为什么不用交易日奇偶**：奇偶会让某一天的**全部**碰撞损失在同一臂，抬高日级构成波动。
逐碰撞哈希在总量上同样对称，但日内大致均分：

| 规则 | FT 让位 | ZS 让位 | 单日碰撞全部归同一臂的天数 | 「归 FT 比例」日间标准差 |
|---|---|---|---|---|
| 逐碰撞 SHA-256 | 1,133 = **2.39%** | 1,137 = **3.26%** | **152 / 588** | **0.289** |
| 交易日奇偶 | 1,139 = 2.41% | 1,131 = 3.24% | 588 / 588 | 0.500 |

（分母为碰撞 ≥2 笔的 588 个交易日。）

### 4.2 让位是有成分偏移的，必须披露

碰撞名字**更便宜但不更不流动**：价格 p50 \$72.9 vs 非碰撞 \$90.7（FT）；
ADV 分位 p50 0.524 vs 0.484。对费用估计的偏差仅 0.9%，可忽略；
对执行偏差段的影响未知，但样本占比 <3.3%。

**必须记住**：让掉的正是两模型**分歧**的名字，而两臂差异恰恰长在分歧处。
让位规则在两臂间严格对称（哈希最低位），**不得固定让同一臂**。
最终报告须给出让位订单的计数与画像。

### 4.3 同向同名订单

同日同名同方向 2,836 笔（FT 的 6.0% / ZS 的 8.1%）。
**预注册为：合并成一笔提交，成交后按名义额比例分配到两臂，两臂记同一成交价。**
（理由：Alpaca 对拆单型非零售流有关注；合并提交更干净。）

## 5. 双影子账本与每日流程

单账户下真实持仓是**执行**的真相，但 FT 与 ZS **各自保有独立的冻结目标与虚拟持仓账本**
——否则发生让位后，次日无从判断哪一臂本来该交易什么。

**每日流程（不得简化）**：

```
1. 两臂各自的影子账本 + 当日分数 -> 各自的再平衡目标
2. 目标 − 影子持仓            -> 两臂的「理想订单」
3. 反向碰撞检测 -> §4.1 哈希让位；同向同名 -> §4.3 合并
4.                            -> 「可执行订单」集合，提交
5. 成交回报 -> 按 §4.3 比例规则回分至各自影子账本
6. sum(两臂影子持仓) == 真实账户持仓  ——   逐股核对
```

**第 6 步不符即当日停机**，查清后方可继续；停机日不计入 §6 的观察日数。

**影子账本记录的是实际分配到的成交，不是理想订单。** 因此让位会让该臂的影子账本
与其模型目标产生漂移——这是预期内的，次日从**影子持仓**重算目标即可。

**小试的估计量是「被交易名字上 fill vs `DlyOpen` 的分布」，不是 P&L。**
账面漂移不影响该估计量的效力。

## 6. 序贯停止规则

**最短观察期：30 个共同交易日。** 不得因为第 5 天 SE 看起来已经很小就停——
5 个日级观测不足以可靠估计日间方差 / HAC。

**此后每 5 个交易日**，只计算两臂**日均成本序列的 NW(5) 标准误**：

- 首次满足 `max(SE_FT, SE_ZS) ≤ 1bp` 时**两臂共同停止**；
- **硬上限 60 个共同交易日**；
- **两臂必须同时停止**——一臂先停会改变另一臂的碰撞环境。

**运行期间不得向任何人展示点估计**，只展示 SE 与已完成日数。
（SE 是讨厌参数，据其停止不污染估计量；据点估计停止会。）

**最终分析必须用 block bootstrap 重演检查时点与停止规则**，
给出考虑了序贯性的区间，而不是把停止时的朴素 CI 直接当结果。

**定档依据**（K14）：所需日数几乎完全由同日相关 ρ 决定，与笔数无关——

| σ_fill \ ρ | 0.0 | 0.2 | 0.5 |
|---|---|---|---|
| 3bp | 1 | 2 | 5 |
| 5bp | 1 | 6 | 13 |
| 10bp | 2 | 22 | **51** |
| 20bp | 8 | 86 | 204 |

（FT，目标 SE ≤ 1bp。60 天上限正好覆盖 σ=10bp / ρ=0.5 一档。）
σ 与 ρ 都不可先验确定，**这正是必须序贯的原因**。

## 7. paper 预演验收（真钱之前的硬门）

用**真实余额**与**同一份碰撞代码**跑 **≥5 个 paper 交易日**，五项全过方可动真钱：

1. 整股 OPG 订单被接受并在竞价成交；
2. 09:28 ET 截止的行为符合预期（含一次故意迟交的验证）；
3. 403 能被复现，且哈希让位规则确实阻止了它；
4. 订单状态回报完整、可归集到逐笔费用；
5. 双影子账本与真实持仓逐股对平（§5 第 6 步）。

**paper 阶段的成交价不得用于任何成本估计**——paper 撮合不是真实竞价。

  **不得外推到别的规模或费率**。
